این پروژه یک مهارت استارتاپی جامع، استاندارد و آماده برای دستیاران و ایجنت‌های کدنویسی هوش مصنوعی (نظیر Claude Code، Cursor، Google Antigravity، OpenAI Codex، GitHub Copilot و ...) است. این مهارت مانع از این می‌شود که ایجنت‌ها بدون درک ساختار شروع به تغییر کدها کنند، کدهای سالم را بازنویسی کنند، سوالات بیهوده بپرسند، در شرایط پیش‌بینی‌نشده کار را متوقف کنند، برای تست کردن، بررسی روت‌ها، دیسپچ مدل‌ها، تست نسخه به‌روزشده یا سرعت سنتز گفتار (`Allow testing updated Edge-TTS?`, `Allow testing TTS synthesis speed?`)، تست پایپ‌لاین STT و تبدیل گفتار به متن (`Allow testing STT pipeline?`, `Allow checking STT providers?`, `Allow testing Groq Whisper STT?`)، بررسی نسخه پکیج‌ها، ارتقای پکیج‌ها (`pip install -U edge-tts`)، مشاهده فایل docker-compose.yml روی سرور (`cat ... docker-compose.yml`)، بررسی کامپوننت‌های فرانت‌اند و سورس‌کد روی سرور (`Allow checking server MobileMenu.tsx? ssh ... "cat ... components/MobileMenu.tsx"`), ارسال فایل با SCP و ریستارت کانتینرها (`Allow deploying updated app files to production?`, `Allow restarting hamzad-ara container?`), اجرای سوئیت‌های ارزیابی و بنچمارک روی سرور (`Allow running 20-utterance Persian evaluation suite?`), بررسی اندپوینت هلث، لاگ کانتینرها، تاریخچه شل یا پوشه `.next` سرور (`Allow checking ARA health endpoint?`, `docker logs`, `history`, `ls .next`)، تکرار اتصال SSH، آپ‌تایم و تست پینگ (`Allow retrying SSH connection?`, `Allow testing SSH to hamzad_server?`), بررسی ترکیبی کانتینر و گیت سرور (`Allow checking server molavi-pro container and git?`), لیست کردن مهارت‌های ریموت یا اندپوینت‌های سرویس (`Allow listing Hermes skills?`), فحص پوشه .next داخل کانتینر (`Allow inspecting container .next directory?`), کپی کردن فایل‌ها یا کامپوننت‌ها با SCP به سرور (`Allow copying components to server?`, `Allow copying page.tsx and robots.ts to server?`, `Allow copying robots.ts to server?`), بررسی رانتایم‌ها یا نسخه‌های نود روی هاست سرور (`Allow checking node on server host? ssh ... "node -v || true"`), بررسی ایمیج‌های داکر روی سرور (`Allow checking docker images on server? ssh ... "docker images | grep ..."`), لیست کردن کانتینرهای فعال روی سرور (`Allow listing containers on hamzad_server? ssh ... "docker ps --format ..."`), آپلود آرشیو فایل‌های بیلد با SCP روی سرور (`Allow uploading build assets archive? scp ... /tmp/*.tar.gz ...`), استعلام مهارت‌ها یا رکوئست بین کانتینری روی سرور (`Allow inspecting Hermes skills from hamzad-ara? ssh ... "docker exec ... http://staging-hermes:8090/api/v1/skills ..."`), دپلوی فایل‌های بیلد به کانتینر و ریستارت با دستورات زنجیره‌ای SSH (`Allow deploying assets to container and restarting?`, `Allow verifying live production authentication suite?`, `Allow verifying live production login endpoint?`, `Allow testing production login with default passcode?`, `Allow testing SSH connectivity to hamzad_server?`, `Allow testing SSH connection with IPQoS=none?`, `Allow running live test?`, `Allow deploying updated code to production?`, `Allow deploying updated ARA files to production server?`, `Allow deploying updated files?`, `Allow executing deployment script? bash /tmp/deploy_molavi.sh`, `Allow deploying assets to hamzad_server?`), استخراج و پرینت تمام مهارت‌های هرمس با اسکریپت پایتون روی سرور (`Allow listing all Hermes skills?`), بررسی اندپوینت‌ها، مستندات docs یا openapi.json هرمس با SSH روی سرور (`Allow checking Hermes API endpoints?`), بررسی محتویات کانتینرها (`docker exec ... ls`)، لیست کردن شاخه‌های گیت سرور (`git branch -a`) یا بررسی وضعیت کانتینرها، شاخه و لاگ‌های گیت سرور اجازه بخواهند یا با پاپ‌آپ‌های مداوم شما را پای سیستم معطل نگه دارند.

## 🌙 پروتکل خواب راحت (Sleep-Well Protocol): اتوماسیون کامل شبانه

بزرگ‌ترین هدف این پروژه این است که:
> **«تسک را به هوش مصنوعی بسپارید، سیستم را روشن بگذارید و راحت بخوابید؛ صبح بیدار شوید و نتیجه تمیز، تست‌شده و آماده را بدون معطل ماندن پشت پاپ‌آپ‌های تاییدیه تحویل بگیرید.»**
>
> *(نکته: روی لپ‌تاپ‌ها از غیرفعال بودن حالت Sleep یا خاموش شدن در اثر بستن در لپ‌تاپ مانند ابزار caffeinate اطمینان حاصل کنید؛ این مهارت تضمین می‌کند عامل هرگز پشت پاپ‌آپ‌های تاییدیه متوقف نشود).*

---

### ❓ چرا ایجنت‌ها مدام درخواست تاییدیه (Approval Prompt) باز می‌کنند؟

در محیط‌های مدرن توسعه هوش مصنوعی (مانند Google Antigravity، Claude Code و Cursor)، یک **سیستم امنیتی قرنطینه (Sandbox)** وجود دارد:
1. **دستورات داخل سندباکس (Standard Sandbox)**: خواندن و نوشتن درون پوشه پروژه، اجرای دستورات معمول گیت (`git status`, `git diff`), بیلد لوکال (`npm run build`, `cargo check`) و تست‌ها (`pytest`, `vitest`) به صورت **۱۰۰٪ خودکار، ساکت و بدون نیاز به تایید شما** اجرا می‌شوند.
2. **چه کارهایی بلافاصله پاپ‌آپ تاییدیه امنیتی باز می‌کنند؟**
   - **توقف در شرایط پیش‌بینی‌نشده و پرسیدن سوالات تک‌تک وسط کار**: وقتی ایجنت به جای ادامه دادن سایر تسک‌ها و تجمیع سوالات برای پایان کار، مکرراً کار را فریز می‌کند.
   - **درخواست تاییدیه برای اجرای تست‌های لایو (`Allow executing production login verification?`, `Allow testing WebSocket auth using venv python?`, `Allow testing live wake-word and meeting WebSocket flow?`, `Allow debugging response for Persian digits?`, `Allow verifying live production authentication suite?`, `Allow verifying live production login endpoint?`, `Allow testing production login with default passcode?`, `Allow testing SSH connectivity to hamzad_server?`, `Allow testing SSH connection with IPQoS=none?`, `Allow running live test?`, `test_live_wake_flow.py`, `verify_prod_login.py`)**: وقتی ایجنت به جای اجرای مستقیم تست‌های خودکار یا ماک کردن لوکال، کاربر را برای اجرای اسکریپت‌های آزمایشی معطل می‌کند.
   - **درخواست تاییدیه برای دانلود لوکال اسکریپت‌ها و کتابخانه‌های فرانت‌اند (`Allow downloading three.min.js locally? curl -sL https://cdnjs...`)**: وقتی ایجنت به جای دانلود مستقیم یا باندل کردن فایل‌های استاتیک و کتابخانه‌های مورد نیاز (`three.min.js`) در فولدرهای پروژه، کاربر را با باز کردن پاپ‌آپ متوقف می‌کند.
   - **درخواست تاییدیه دسترسی نوشتن به مسیر یا فایل (`Allow write access to this path? /Users/taghimolavi/ivnanewscom/app/Models/News.php`, `Allow write access to this path? /Users/taghimolavi/ivnanewscom/routes/api.php`)**: وقتی ایجنت به جای نوشتن و ویرایش خودکار فایل‌ها، روت‌ها و تنظیمات پروژه با ابزارهای فایل، کاربر را برای اجازه دسترسی به مسیر فایل متوقف می‌کند.
   - **درخواست تاییدیه برای تست لایو احراز هویت، اجرای اسکریپت‌های وریفای و دیباگ ریسپانس روی پروداکشن (`Allow executing production login verification?`, `Allow debugging response for Persian digits?`, `Allow verifying live production authentication suite?`, `Allow verifying live production login endpoint?`, `Allow testing production login with default passcode?`)**: تلاش اشتباه برای ارسال رکوئست‌های زنده، اسکریپت‌های وریفای لاگین (`verify_prod_login.py`) یا دیباگ خروجی با ارقام فارسی (`ara۲۰۲۶`) به `/api/auth/login` پروداکشن به جای تست لوکال با TestClient.
   - **درخواست تاییدیه برای تست ارتباط SSH با فلگ‌های verbose یا آپشن‌های IPQoS (`Allow testing SSH connectivity to hamzad_server? ssh -v ...`, `Allow testing SSH connection with IPQoS=none? ssh -o IPQoS=none ...`)**: تلاش اشتباه برای پروب اتصال یا فلگ‌های عیب‌یابی شبکه به جای سوئیچ به راستی‌آزمایی لوکال.
   - **درخواست تاییدیه برای تست‌های روتین (`Allow testing /api/... ?`)**: وقتی ایجنت به جای تصمیم‌گیری مستقل، کاربر را معطل می‌کند تا بپرسد آیا فلان اندپوینت یا اسکریپت SSH را تست کند یا خیر.
   - **درخواست تاییدیه برای تست دیسپچ مدل و روترهای استدلال (`Allow testing central model dispatch? ssh ...`)**: پرسیدن تاییدیه برای ارسال پرامپت و تست لایو مدل‌ها روی کانتینرهای ریموت به جای ماک کردن لوکال.
   - **درخواست تاییدیه برای تست سرعت صوت، سنتز گفتار یا تست نسخه به‌روزشده Edge-TTS (`Allow testing TTS synthesis speed?`, `Allow testing updated Edge-TTS? ssh ...`)**: پرسیدن تاییدیه برای اجرای بنچمارک سرعت، بررسی نسخه به‌روزشده یا تولید صدا روی کانتینرهای ریموت به جای تست و ماک کردن لوکال.
   - **درخواست تاییدیه برای تست پایپ‌لاین تبدیل گفتار به متن (STT)، پرووایدرها یا Groq Whisper (`Allow testing STT pipeline?`, `Allow checking STT providers?`, `Allow testing Groq Whisper STT?`)**: پرسیدن تاییدیه برای اجرای تست رونویسی صوت روی کانتینرهای ریموت به جای تست و ماک کردن لوکال.
   - **درخواست تاییدیه برای بررسی نسخه پکیج‌ها و وابستگی‌ها (`Allow checking edge-tts version? ssh ... "pip show ..."`):** تلاش اشتباه ایجنت برای بررسی کتابخانه‌ها از طریق SSH به جای خواندن مانیفست‌های لوکال.
   - **درخواست تاییدیه برای ارتقا و تغییر پکیج‌ها روی سرور (`Allow upgrading edge-tts? ssh ... "pip install -U ..."`):** تلاش اشتباه ایجنت برای اجرای دستورات ارتقای پکیج از طریق SSH روی کانتینرهای ریموت به جای تغییر مانیفست‌های لوکال.
   - **درخواست تاییدیه برای مشاهده و خواندن کانفیگ‌های دپلوی یا docker-compose روی سرور (`Allow viewing server docker-compose.yml? ssh ... "cat ... docker-compose.yml"`):** تلاش اشتباه ایجنت برای خواندن مانیفست‌های دپلوی از طریق SSH به جای بررسی مستقیم فایل‌های پروژه در مخزن محلی.
   - **درخواست تاییدیه برای بررسی محتویات کانتینرها (`Allow checking container contents? ssh ... "docker exec molavi-pro-web ls -la /app"`):** تلاش اشتباه ایجنت برای کاوش ساختار فایل‌ها و دایرکتوری‌های کانتینر از طریق SSH به جای بررسی ساختار مخزن لوکال و تنظیمات `Dockerfile`.
   - **درخواست تاییدیه برای مشاهده و خواندن کامپوننت‌های فرانت‌اند یا سورس‌کد روی سرور (`Allow checking server MobileMenu.tsx? ssh ... "cat ... components/MobileMenu.tsx"`):** تلاش اشتباه ایجنت برای خواندن کامپوننت‌های UI و فایل‌های پروژه از طریق SSH به جای بررسی مستقیم فایل‌ها در مخزن لوکال.
   - **درخواست تاییدیه برای انتقال فایل با SCP یا ریستارت کانتینرها (`Allow deploying updated app files to production?`, `Allow restarting hamzad-ara container?`):** تلاش اشتباه ایجنت برای اجرای دستورات استقرار ریموت و ریستارت کانتینر وسط تسک به جای آماده‌سازی و اعتبارسنجی لوکال.
   - **درخواست تاییدیه برای اجرای سوئیت‌های ارزیابی و بنچمارک روی سرور (`Allow running 20-utterance Persian evaluation suite?`):** تلاش اشتباه ایجنت برای کپی و اجرای اسکریپت‌های بنچمارک روی سرورهای عملیاتی به جای اجرای لوکال با داده‌های ماک.
   - **درخواست تاییدیه برای فحص اندپوینت‌های سلامت، لاگ کانتینرها، تاریخچه دستورات یا پوشه .next (`Allow checking ARA health endpoint?`, `docker logs`, `history`, `ls .next`):** تلاش اشتباه ایجنت برای خواندن لاگ‌ها، دستورات ترمینال و فایل‌های بیلد سرور از طریق SSH.
   - **درخواست تاییدیه برای تلاش مجدد یا تست اتصال SSH و آپ‌تایم (`Allow retrying SSH connection?`, `Allow testing SSH to hamzad_server?`):** تلاش اشتباه ایجنت برای پینگ، تست اتصال یا اجرای `uptime` و `echo` روی سرور ریموت در زمان تایم‌اوت به جای فال‌بک محلی.
   - **درخواست تاییدیه برای بررسی ترکیبی کانتینر و وضعیت گیت سرور (`Allow checking server molavi-pro container and git?`):** اجرای پایپ‌لاین‌های ترکیبی SSH (`docker ps ... && cd ... && git status -s`) به جای تفکیک استاتیک.
   - **درخواست تاییدیه برای استعلام مهارت‌ها و اندپوینت‌های داخلی سرویس (`Allow listing Hermes skills?`):** تلاش برای اجرای `docker exec ... httpx.get` روی سرور ریموت به جای خواندن مانیفست‌های رجیستری محلی.
   - **درخواست تاییدیه برای بررسی پوشه بیلد .next داخل کانتینر سرور (`Allow inspecting container .next directory?`):** اجرای `docker exec ... ls -la /app/.next` روی سرور به جای بررسی بیلد لوکال با `npm run build`.
   - **درخواست تاییدیه برای کپی موردی فایل‌ها و صفحات با SCP به سرور (`Allow copying components to server?`, `Allow copying page.tsx and robots.ts to server?`, `Allow copying robots.ts to server?`):** تلاش اشتباه برای کپی دستی فایل‌ها با SCP به جای کامیت و دپلوی استاندارد با اسکریپت رلیز.
   - **درخواست تاییدیه برای بررسی وضعیت کانتینرها، شاخه یا لاگ گیت سرور (`Allow checking server container and git status?`, `Allow checking server git branch and log?`, `Allow listing git branches on server?`, `Allow checking molavi-pro container on server?`):** تلاش اشتباه ایجنت برای اجرای `docker ps` یا خواندن `git branch` و `git log` روی سرور ریموت به جای بررسی مخزن محلی.
   - **درخواست تاییدیه برای بررسی روت‌ها و سورس‌کد ریموت (`Allow checking model router endpoints? ssh ...`)**: تلاش اشتباه ایجنت برای اتصال SSH به سرور و خواندن فایل‌های پروژه (`routers/models.py`) به جای بررسی فایل‌های محلی خود مخزن.
   - **درخواست خروج از سندباکس (`BypassSandbox: true`)**: اگر ایجنت بخواهد دسترسی آزاد به کارت شبکه یا دیسک اصلی سیستم داشته باشد و دسترسی پیش‌فرض ثبت نشده باشد.
   - **پینگ و کرول دامنه‌های عمومی زنده (`curl https://...`)**: ارسال درخواست‌های HTTP به اینترنت زنده برای راستی‌آزمایی کد.
   - **دستورات ریموت سرخود (`ssh`, `scp`, `docker images` روی سرور ریموت)**: وقتی ایجنت به جای خواندن فایل‌های کانفیگ، تلاش می‌کند مستقیماً به سرور یا کانتینرهای ریموت وصل شود.
   - **دستورات داخلی و عمیق گیت (`git count-objects`, `git fsck`)**: دستورات سیستمی گیت که خارج از پیشوند‌های مجاز هستند و زنگ هشدار امنیتی را فعال می‌کنند.
   - **تلاش برای تغییر فایل‌های خارج از پروژه**: دستکاری تنظیمات سراسری سیستم یا فایل‌های IDE (مانند `config.json`).
   - **زنجیره‌های طولانی شل با پایپ (`cmd1 && cmd2 | grep ... | awk ...`)**: پایپ‌های چندگانه باعث می‌شوند سیستم تشخیص پیشوند نتواند دستور را به عنوان مجاز تشخیص دهد و تاییدیه مجدد بخواهد.
   - **دستورات تکه‌تکه برای اتوماسیون مرورگر یا سیستم (`osascript -e '...'`)**: اجرای مکرر قطعه‌کدهای خطی اپل‌اسکریپت که مرتب هشدار دسترسی کنترل سیستم ایجاد می‌کنند.

### 🛠️ این مهارت چگونه جلوی تمام این پاپ‌آپ‌ها را می‌گیرد؟

1. **تداوم کار در شرایط پیش‌بینی‌نشده و تجمیع سوالات در پایان کار («ادامه بده و همه رو آخرش یه جا بپرس»):** در برخورد با ابهامات یا شرایط پیش‌بینی‌نشده، ایجنت کار را متوقف نمی‌کند؛ تصمیم پیش‌فرض امن و برگشت‌پذیر را اتخاذ کرده، کارهای دیگر را به سرانجام می‌رساند و تمام سوالات تجمیع‌شده را در انتهای تسک یک‌جا می‌پرسد.
2. **تصمیم‌گیری مستقل برای تست و اعتبارسنجی (خودش تصمیم بگیره):** ایجنت هرگز سوالات تاییدی مثل «Allow testing /api/... ?»، «Allow retrying SSH connection?»، «Allow checking server molavi-pro container and git?»، «Allow listing Hermes skills?»، «Allow inspecting container .next directory?» یا «Allow copying components to server?» نمی‌پرسد. ایجنت موظف است خودش تصمیم بگیرد و فرآیند اعتبارسنجی را از طریق تست‌های لوکال، ماک‌ها، تست‌دابل‌ها و سرورهای محلی انجام دهد و نتیجه را در گزارش نهایی درج کند.
3. **بررسی سورس‌کد و روت‌ها به صورت کاملاً محلی:** تمام روت‌ها، دکوریتورها (`@router.get`, `@router.post`) و مدل‌ها مستقیماً از فایل‌های داخل مخزن لوکال خوانده می‌شوند، بدون هیچ اتصال SSH غیرضروری.
4. **بررسی استاتیک وابستگی‌ها و پکیج‌ها:** اطلاعات مربوط به نسخه‌ها و پکیج‌ها (`edge-tts`, `httpx`, ...) از روی فایل‌های مانیفست (`requirements.txt`, `pyproject.toml`, `package.json`, `Dockerfile`) بدون اجرای `pip show` روی سرور خوانده می‌شود.
5. **ارتقا و مدیریت پکیج‌ها در مانیفست‌های لوکال مخزن:** در صورت نیاز به ارتقای نسخه‌ها یا رفع باگ پکیج‌ها، ایجنت نسخه‌ها را مستقیماً در فایل‌های مانیفست پروژه تغییر داده و با تست‌های لوکال اعتبارسنجی می‌کند، نه با اجرای دستورات `pip install -U` روی سرورهای ریموت.
6. **بررسی مانیفست‌های دپلوی و کانفیگ‌ها به صورت محلی:** اطلاعات سرویس‌ها، فایل‌های داکر و دپلوی (`docker-compose.yml`, `Dockerfile`, `nginx.conf`) مستقیماً از روی فایل‌های مخزن لوکال خوانده می‌شوند و نیازی به اجرای دستورات `cat` از طریق SSH روی سرور ریموت نیست.
7. **بررسی وضعیت کانتینرها، شاخه‌ها و لاگ‌های گیت به صورت محلی:** اطلاعات سرویس‌ها، کانتینرها و پورت‌ها از روی مانیفست‌های لوکال (`docker-compose.yml`, `Dockerfile`) و وضعیت گیت (شاخه جاری با `git branch --show-current`, لیست کامل شاخه‌ها با `git branch -a`, لاگ‌ها با `git log -n 5` و وضعیت تغییرات با `git status -s`) مستقیماً از روی مخزن محلی خوانده می‌شود، نه با اجرای SSH روی سرور ریموت.
8. **بررسی ساختار فایل‌ها و دایرکتوری‌های کانتینر به صورت محلی:** ساختار فایل‌ها، دایرکتوری‌های پروژه و مسیرهای اپلیکیشن (`/app`، `/workspace`) مستقیماً از روی فایل‌های مخزن لوکال و تنظیمات `Dockerfile` (دستورات WORKDIR و COPY) و ولوم‌های `docker-compose.yml` خوانده و بررسی می‌شوند، بدون اجرای دستورات کاوش فایل نظیر `docker exec ... ls` روی سرور ریموت.
9. **ماک کردن روترهای مدل و دیسپچ مرکزی:** اعتبارسنجی روترهای استدلال هوش مصنوعی و دیسپچر مدل‌ها در محیط لوکال با ترنسپورت‌های ماک‌شده انجام می‌شود تا نیازی به تست روی سرورهای ریموت نباشد.
10. **ماک کردن سرویس‌های صوت، سنتز گفتار (TTS) و کتابخانه به‌روزشده Edge-TTS:** اعتبارسنجی سرویس‌های صوت (`TTSService`)، کتابخانه به‌روزشده Edge-TTS، چانک‌های صوتی و تاخیر سنتز در محیط لوکال با داده‌های ساختگی صوتی و توابع ماک ناهمگام انجام می‌شود تا نیازی به اجرای اسکریپت‌های بنچمارک روی سرورهای ریموت نباشد.
11. **ماک کردن سرویس‌های تبدیل گفتار به متن (STT)، پرووایدرها و Groq Whisper:** اعتبارسنجی سرویس‌های استخراج متن از صوت (`STTService`)، تابع `transcribe_audio_bytes`، بررسی تنظیمات پرووایدرها و تست Groq Whisper در محیط لوکال با داده‌های ساختگی صوتی و ماک‌های ناهمگام HTTP انجام می‌شود تا نیازی به تست رونویسی روی سرورهای ریموت نباشد.
12. **بررسی کامپوننت‌های فرانت‌اند و سورس‌کد به صورت محلی:** فایل‌های رابط کاربری، کامپوننت‌های فرانت‌اند (`components/MobileMenu.tsx`، فایل‌های `.tsx`، `.jsx`، `.vue`) و تمپلیت‌ها مستقیماً از روی فایل‌های مخزن لوکال خوانده و بررسی می‌شوند، بدون اجرای دستورات `cat` از طریق SSH روی سرور ریموت.
13. **مدیریت محلی استقرار و دوری از SCP سرخود:** آماده‌سازی، بسته‌بندی و تست تغییرات در مخزن محلی انجام می‌شود و از ارسال تکه‌تکه فایل‌ها با SCP یا ریستارت کانتینرها در حین تسک خودداری می‌شود.
14. **اجرای محلی سوئیت‌های ارزیابی و بنچمارک:** سوئیت‌های تست و بنچمارک‌های چند جمله‌ای (`test_20_persian_utterances.py`) به صورت محلی و با مدل‌ها یا داده‌های ماک اجرا می‌شوند، نه با اجرای مستقیم روی کانتینرهای پروداکشن ریموت.
15. **عیب‌یابی محلی سلامت سیستم، لاگ‌ها و فایل‌های بیلد:** روت‌های سلامت (`/api/health`)، لاگ‌های خطا، تاریخچه دستورات و خروجی‌های بیلد (`.next`) به صورت محلی از کد و بیلد لوکال بررسی می‌شوند، بدون ارسال دستورات SSH `curl`, `docker logs`, `history` یا `ls .next`.
16. **فال‌بک خودکار قطعی و دوری از تست پینگ و آپ‌تایم SSH:** در صورت بروز تایم‌اوت، کندی یا خطای اتصال SSH، ایجنت نباید کاربر را با پرامپت‌های تکرار اتصال، آپ‌تایم یا اکو معطل کند؛ بلکه بلافاصله به راستی‌آزمایی لوکال، بررسی ماک‌ها و ساخت کدهای مستقل سوئیچ می‌کند و گزارش عدم دسترسی را در انتهای تسک درج می‌نماید.
17. **تفکیک خودکار و محلی دستورات ترکیبی کانتینر و گیت:** به جای اجرای زنجیره‌ای دستورات SSH برای بررسی کانتینر و وضعیت گیت، کانفیگ کانتینرها به صورت استاتیک و وضعیت شاخه و کامیت‌های گیت به شکل کاملاً محلی بررسی می‌شوند.
18. **کشف محلی مهارت‌ها و قابلیت‌های میکروسرویس‌ها:** لیست مهارت‌ها، ابزارها و کدهای سرویس‌ها (نظیر هرمس) مستقیماً از روی مانیفست‌ها و اسناد داخل مخزن (`hermes-skill-discovery-registry-v1.json`) خوانده می‌شوند و نیازی به فراخوانی ریموت API با `docker exec` نیست.
19. **اعتبارسنجی بیلد محلی به جای بازرسی ریموت پوشه .next:** ساختار و خروجی پوشه `.next/` مستقیماً با بیلد لوکال (`npm run build`) اعتبارسنجی می‌شود، بدون نیاز به ارسال دستورات بازرسی دایرکتوری در کانتینر ریموت.
20. **استقرار استاندارد مبتنی بر گیت و پایان کپی دستی فایل با SCP:** هرگونه تغییر در سورس‌کد به جای ارسال تکه‌تکه با SCP، به عنوان کامیت در گیت ثبت شده و فرآیند دپلوی منحصراً از طریق اسکریپت رسمی انتشار (`deploy.sh`) انجام می‌پذیرد.
21. **شناسایی خودکار رانتایم‌ها و نسخه‌های محیطی:** نیازمندی‌های نسخه Node.js یا پایتون مستقیماً از روی مانیفست‌های مخزن لوکال (`package.json` فیلد engines، فایل `.nvmrc`، `Dockerfile`) خوانده و تعیین می‌شود، بدون ارسال پروب‌های SSH نظیر `node -v` به هاست سرور.
22. **شناسایی خودکار ایمیج‌ها و تگ‌های داکر:** مشخصات ایمیج‌ها، تگ‌ها و ایمیج‌های پایه مستقیماً از روی مانیفست‌های لوکال مخزن (`docker-compose.yml`, `Dockerfile`) استخراج و بررسی می‌شوند، بدون ارسال دستورات SSH نظیر `docker images | grep ...` به سرور.
23. **شناسایی خودکار ساختار و توپولوژی کانتینرها:** اسامی کانتینرها، سرویس‌ها و پورت‌ها مستقیماً از روی مانیفست‌های لوکال (`docker-compose.yml`, `Dockerfile`) استخراج و بررسی می‌شوند، بدون اجرای دستورات SSH نظیر `docker ps --format ...` روی سرور ریموت.
24. **اعتبارسنجی بیلد محلی و مهار آپلود دستی آرشیوها با SCP:** دارایی‌های بیلد (`.next`) مستقیماً به صورت محلی بیلد و اعتبارسنجی می‌شوند و از آپلودهای موردی تاربال‌ها با SCP به سرور پرهیز شده و استقرار صرفاً از طریق اسکریپت رسمی انتشار انجام می‌پذیرد.
25. **شناسایی خودکار قابلیت‌های میکروسرویس‌ها و ارتباطات بین کانتینری:** لیست مهارت‌ها و اندپوینت‌های داخلی بین کانتینرها مستقیماً از روی فایل‌های رجیستری (`hermes-skill-discovery-registry-v1.json`, `docker-compose.yml`) استخراج شده و به صورت محلی ماک می‌شوند، بدون ارسال پروب‌های SSH بین کانتینری.
26. **استقرار یکپارچه و مهار هات‌پچ‌های موقت کانتینر:** فرآیند دپلوی دارایی‌ها صرفاً از طریق اسکریپت رسمی انتشار (`deploy.sh`) انجام شده و از زنجیره دستورات SSH برای اکسترکت، کپی به داخل کانتینر (`docker cp`) یا اجرای اسکریپت‌های موقت (`/tmp/deploy_molavi.sh`) همراه با تاییدیه پرهیز می‌شود.
27. **استخراج استاتیک کاتالوگ مهارت‌ها و ابزارها:** لیست کامل مهارت‌ها و قابلیت‌های سرویس‌ها منحصراً از فایل‌های رجیستری محلی (`hermes-skill-discovery-registry-v1.json`) خوانده شده و از اجرای اسکریپت‌های SSH برای واکشی فهرست کامل مهارت‌ها پرهیز می‌شود.
28. **کشف استاتیک روت‌ها و اسکیماهای API:** اندپوینت‌ها، کنترلرها و اسکیماهای API مستقیماً از روی سورس‌کدهای مخزن لوکال خوانده می‌شوند، بدون ارسال پروب‌های SSH به مسیرهای `/docs` یا `/openapi.json` روی سرور.

31. **ویرایش و نوشتن مستقل فایل‌ها بدون درخواست اجازه مسیر (`Allow write access to this path?`):** فایل‌های سورس‌کد، مدل‌های برنامه (`app/Models/News.php`)، فایل‌های روت (`routes/api.php`)، کنترلرها و کانفیگ‌ها در پروژه‌های مختلف مستقیماً با ابزارهای محلی ویرایش فایل بدون باز کردن پاپ‌آپ درخواست اجازه مسیر ویرایش می‌شوند.
32. **دانلود و مدیریت مستقل اسکریپت‌ها و کتابخانه‌های استاتیک بدون درخواست تاییدیه (`Allow downloading three.min.js locally?`):** کتابخانه‌ها، اسکریپت‌های کلاینت (`three.min.js`) و است‌های مورد نیاز به صورت مستقل و بدون باز کردن پاپ‌آپ دانلود یا باندل می‌شوند.
31. **حذف پروب‌های شبکه و آپشن‌های SSH:** به جای تست‌های مداوم اتصال SSH با فلگ‌های `ssh -v` یا `-o IPQoS=none`، ایجنت بلافاصله به بررسی لوکال سوئیچ می‌کند و اتصال را با تاییدیه معطل نمی‌سازد.
32. **اجرای خودکار و ماک محلی تست‌های لایو (`Allow running live test?`):** تست‌های یکپارچگی، رخدادهای بیدارباش و پایپ‌لاین‌های سیستم به صورت لوکال با ماک‌ها اعتبارسنجی می‌شوند یا سوئیت‌های تست مستقیماً بدون پاپ‌آپ تاییدیه اجرا می‌گردند.
33. **تست و ماک محلی پایپ‌لاین وب‌سوکت، احراز هویت و Wake-Word:** پروتکل وب‌سوکت، توکن لاگین با پس‌کد، اعتبارسنجی احراز هویت وب‌سوکت (`Allow testing WebSocket auth using venv python?`)، رخدادهای جلسه (`session_ready`) و تشخیص کلمه بیدارباش مستقیماً به صورت محلی با تست‌کلاینت‌ها و فیچرهای ماک راستی‌آزمایی می‌شوند، بدون اجرای اسکریپت ریموت در کانتینر پروداکشن یا اتصال زنده.
34. **کشف و ماک محلی اندپوینت‌های میکروسرویس‌ها:** روت‌ها، مسیرهای سلامت و مدل‌های میکروسرویس‌ها (نظیر هرمس) مستقیماً از روی کدهای لوکال خوانده شده و با کلاینت‌های ماک تست می‌شوند، بدون ارسال حلقه‌های پروب SSH روی سرور.
35. **استقرار استاندارد گیت و مهار سینک چند فایله SCP و پایپ SSH cat:** تمام تغییرات به عنوان کامیت گیت ثبت شده و استقرار صرفاً از طریق اسکریپت رسمی انتشار (`deploy.sh`) انجام می‌پذیرد و از کپی‌های دستی چند فایله با SCP یا ریدایرکت `ssh cat >` اجتناب می‌شود.
36. **ممنوعیت آزمون‌های زنده اینترنتی و ریموت**: ایجنت ملزم است کدهایش را با تست‌های لوکال، بیلد داخلی و سرور لوپ‌بک (`127.0.0.1`) راستی‌آزمایی کند نه با ارسال رکوئست به دامنه‌های عمومی یا اجرای دستورات ریموت روی سرور.
37. **اتوماسیون مرورگر و OS با متد «رانر تکی» (Single-Runner Batching)**: اگر کاربر از ایجنت بخواهد تب‌های فعال مرورگر (مثل cPanel، کنسول‌های کلود یا فیگما) را بررسی کند، ایجنت **نباید** ده‌ها خط دستور شل تکه‌تکه اجرا کند؛ بلکه یک اسکریپت تمیز پایتون یا اپل‌اسکریپت در پوشه پروژه می‌نویسد و آن را یک‌بار به شکل تمیز اجرا و خروجی ساختاریافته (JSON) را دریافت می‌کند.
38. **بررسی استاتیک دپلوی**: اطلاعات پورت‌ها، سرویس‌ها و داکر را مستقیماً از روی `docker-compose.yml` و `Dockerfile` می‌خواند نه با شلیک دستورات مکرر SSH.
39. **حفظ استقلال پروژه**: هرگز فایل‌های کانفیگ سیستمی بیرون از پروژه را دستکاری نمی‌کند.

### 🛡️ راهنمای فعال‌سازی دسترسی کامل (Full Access Setup)

اگر مایلید به ابزار کدنویسی خود دسترسی کامل بدهید تا در هیچ شرایطی پاپ‌آپ باز نکند، طبق راهنمای زیر عمل کنید:

#### ۱. گوگل آنتی‌گرویتی (Google Antigravity)
در فایل تنظیمات کاربری `~/.gemini/config/config.json`، کلید `globalPermissionGrants.allow` را با پیشوندهای مجاز تکمیل کنید:
```json
{
  "globalPermissionGrants": {
    "allow": [
      "command(git)",
      "command(pnpm)",
      "command(npm)",
      "command(python3)",
      "command(node)",
      "command(ssh)",
      "command(docker)",
      "command(curl)",
      "command(osascript)",
      "unsandboxed(python3)",
      "unsandboxed(bash)",
      "unsandboxed(osascript)",
      "unsandboxed(ssh)",
      "unsandboxed(docker)",
      "unsandboxed(curl)"
    ]
  }
}
```

#### ۲. کلود کد (Claude Code)
دستورات مجاز پروژه یا محیط را در کانفیگ مشخص کنید:
```json
{
  "allowedCommands": [
    "git *",
    "pnpm *",
    "npm *",
    "python3 *",
    "pytest *",
    "node *"
  ]
}
```

#### ۳. کرسر (Cursor)
با افزودن فایل `templates/AGENTS.md` به ریشه پروژه یا کانفیگ `.cursorrules`، ایجنت را موظف کنید که همواره درون سندباکس و با متد رانر تکی عمل کند.

## 🛡️ ۷ قانون طلایی این مهارت

1. **کشف و شناخت پروژه قبل از هر اقدامی (Discovery):** بررسی ساختار دایرکتوری‌ها، فایل‌های راهنما (`README`)، معماری (`docs/`)، نیازمندی‌ها (`package.json`, `go.mod`, `Cargo.lock`, `pyproject.toml`)، متغیرهای محیطی و فایل‌های داکر و استقرار.

3. **درک وضعیت گیت (Git Understanding):** بررسی شاخه فعلی (`branch`)، وضعیت درخت کاری (`git status`) و حفظ تمام کدهای کامیت‌نشده‌ی کاربر.
4. **ساخت مدل ذهنی (Mental Model):** درک هدف بیزینس، معماری لایه‌ها، جریان داده‌ها و استراتژی تست قبل از تغییر حتی یک فایل.
5. **سیاست ممنوعیت سوالات ناتوان‌کننده و تاییدیه‌های تست (خودش تصمیم بگیره):** ایجنت نباید برای تست کردن، اجرای ماک، یا اعتبارسنجی اندپوینت‌ها اجازه بخواهد؛ باید خودش شجاعانه و مستقل تصمیم بگیرد، با ابزارهای لوکال اعتبارسنجی کند و گزارش را در پایان کار ارائه دهد. سوال فقط زمانی پرسیده می‌شود که اطلاعات اصلاً وجود نداشته باشد یا تغییر تخریبی باشد.
6. **پروتکل پاسخگویی استاندارد مهندسی:** ارائه تحلیل در قالب ۴ بخش در اولین پاسخ:
   - `## Understanding` (درک پروژه)
   - `## Current State` (وضعیت فعلی کد و گیت)
   - `## Plan` (برنامه اجرایی مرحله‌به‌مرحله)
   - `## Blocking Questions` (فقط موانع واقعی، در غیر این صورت هیچ)
7. **گزارش شفاف پایان کار (Completion Report):** ارائه گزارش نهایی شامل وضعیت موفقیت (`STATUS`)، فایل‌های تغییریافته (`CHANGES`)، اعتبارسنجی و تست‌ها (`VALIDATION`)، وضعیت استقرار (`DEPLOYMENT`) و موارد باقی‌مانده (`REMAINING`).
