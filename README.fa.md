این پروژه یک مهارت استارتاپی جامع، استاندارد و آماده برای دستیاران و ایجنت‌های کدنویسی هوش مصنوعی (نظیر Claude Code، Cursor، Google Antigravity، OpenAI Codex، GitHub Copilot و ...) است. این مهارت مانع از این می‌شود که ایجنت‌ها بدون درک ساختار شروع به تغییر کدها کنند، کدهای سالم را بازنویسی کنند، سوالات بیهوده بپرسند، در شرایط پیش‌بینی‌نشده کار را متوقف کنند، برای تست کردن، بررسی روت‌ها، دیسپچ مدل‌ها، بررسی نسخه پکیج‌ها، ارتقای پکیج‌ها (`pip install -U edge-tts`) یا بررسی وضعیت کانتینرها، شاخه و لاگ‌های گیت سرور اجازه بخواهند یا با پاپ‌آپ‌های مداوم شما را پای سیستم معطل نگه دارند.

## 🌙 پروتکل خواب راحت (Sleep-Well Protocol): اتوماسیون کامل شبانه

بزرگ‌ترین هدف این پروژه این است که:
> **«تسک را به هوش مصنوعی بسپارید، لپ‌تاپ را ببندید و راحت بخوابید؛ صبح بیدار شوید و نتیجه تمیز، تست‌شده و آماده را بدون معطل ماندن پشت پاپ‌آپ‌های تاییدیه تحویل بگیرید.»**

### ❓ چرا ایجنت‌ها مدام درخواست تاییدیه (Approval Prompt) باز می‌کنند؟

در محیط‌های مدرن توسعه هوش مصنوعی (مانند Google Antigravity، Claude Code و Cursor)، یک **سیستم امنیتی قرنطینه (Sandbox)** وجود دارد:
1. **دستورات داخل سندباکس (Standard Sandbox)**: خواندن و نوشتن درون پوشه پروژه، اجرای دستورات معمول گیت (`git status`, `git diff`), بیلد لوکال (`npm run build`, `cargo check`) و تست‌ها (`pytest`, `vitest`) به صورت **۱۰۰٪ خودکار، ساکت و بدون نیاز به تایید شما** اجرا می‌شوند.
2. **چه کارهایی بلافاصله پاپ‌آپ تاییدیه امنیتی باز می‌کنند؟**
   - **توقف در شرایط پیش‌بینی‌نشده و پرسیدن سوالات تک‌تک وسط کار**: وقتی ایجنت به جای ادامه دادن سایر تسک‌ها و تجمیع سوالات برای پایان کار، مکرراً کار را فریز می‌کند.
   - **درخواست تاییدیه برای تست‌های روتین (`Allow testing /api/... ?`)**: وقتی ایجنت به جای تصمیم‌گیری مستقل، کاربر را معطل می‌کند تا بپرسد آیا فلان اندپوینت یا اسکریپت SSH را تست کند یا خیر.
   - **درخواست تاییدیه برای تست دیسپچ مدل و روترهای استدلال (`Allow testing central model dispatch? ssh ...`)**: پرسیدن تاییدیه برای ارسال پرامپت و تست لایو مدل‌ها روی کانتینرهای ریموت به جای ماک کردن لوکال.
   - **درخواست تاییدیه برای تست سرعت صوت و سنتز گفتار (`Allow testing TTS synthesis speed? ssh ...`)**: پرسیدن تاییدیه برای اجرای بنچمارک سرعت یا تولید صدا روی کانتینرهای ریموت به جای تست و ماک کردن لوکال.
   - **درخواست تاییدیه برای بررسی نسخه پکیج‌ها و وابستگی‌ها (`Allow checking edge-tts version? ssh ... "pip show ..."`):** تلاش اشتباه ایجنت برای بررسی کتابخانه‌ها از طریق SSH به جای خواندن مانیفست‌های لوکال.
   - **درخواست تاییدیه برای ارتقا و تغییر پکیج‌ها روی سرور (`Allow upgrading edge-tts? ssh ... "pip install -U ..."`):** تلاش اشتباه ایجنت برای اجرای دستورات ارتقای پکیج از طریق SSH روی کانتینرهای ریموت به جای تغییر مانیفست‌های لوکال.
   - **درخواست تاییدیه برای بررسی وضعیت کانتینرها، شاخه یا لاگ گیت سرور (`Allow checking server container and git status?`, `Allow checking server git branch and log? ssh ... "git branch ... && git log ..."`):** تلاش اشتباه ایجنت برای اجرای `docker ps` یا خواندن `git branch` و `git log` روی سرور ریموت به جای بررسی مخزن محلی.
   - **درخواست تاییدیه برای بررسی روت‌ها و سورس‌کد ریموت (`Allow checking model router endpoints? ssh ...`)**: تلاش اشتباه ایجنت برای اتصال SSH به سرور و خواندن فایل‌های پروژه (`routers/models.py`) به جای بررسی فایل‌های محلی خود مخزن.
   - **درخواست خروج از سندباکس (`BypassSandbox: true`)**: اگر ایجنت بخواهد دسترسی آزاد به کارت شبکه یا دیسک اصلی سیستم داشته باشد و دسترسی پیش‌فرض ثبت نشده باشد.
   - **پینگ و کرول دامنه‌های عمومی زنده (`curl https://...`)**: ارسال درخواست‌های HTTP به اینترنت زنده برای راستی‌آزمایی کد.
   - **دستورات ریموت سرخود (`ssh`, `scp`, `docker images` روی سرور ریموت)**: وقتی ایجنت به جای خواندن فایل‌های کانفیگ، تلاش می‌کند مستقیماً به سرور یا کانتینرهای ریموت وصل شود.
   - **دستورات داخلی و عمیق گیت (`git count-objects`, `git fsck`)**: دستورات سیستمی گیت که خارج از پیشوند‌های مجاز هستند و زنگ هشدار امنیتی را فعال می‌کنند.
   - **تلاش برای تغییر فایل‌های خارج از پروژه**: دستکاری تنظیمات سراسری سیستم یا فایل‌های IDE (مانند `config.json`).
   - **زنجیره‌های طولانی شل با پایپ (`cmd1 && cmd2 | grep ... | awk ...`)**: پایپ‌های چندگانه باعث می‌شوند سیستم تشخیص پیشوند نتواند دستور را به عنوان مجاز تشخیص دهد و تاییدیه مجدد بخواهد.
   - **دستورات تکه‌تکه برای اتوماسیون مرورگر یا سیستم (`osascript -e '...'`)**: اجرای مکرر قطعه‌کدهای خطی اپل‌اسکریپت که مرتب هشدار دسترسی کنترل سیستم ایجاد می‌کنند.

### 🛠️ این مهارت چگونه جلوی تمام این پاپ‌آپ‌ها را می‌گیرد؟

1. **تداوم کار در شرایط پیش‌بینی‌نشده و تجمیع سوالات در پایان کار («ادامه بده و همه رو آخرش یه جا بپرس»):** در برخورد با ابهامات یا شرایط پیش‌بینی‌نشده، ایجنت کار را متوقف نمی‌کند؛ تصمیم پیش‌فرض امن و برگشت‌پذیر را اتخاذ کرده، کارهای دیگر را به سرانجام می‌رساند و تمام سوالات تجمیع‌شده را در انتهای تسک یک‌جا می‌پرسد.
2. **تصمیم‌گیری مستقل برای تست و اعتبارسنجی (خودش تصمیم بگیره):** ایجنت هرگز سوالات تاییدی مثل «Allow testing /api/models/generate? ssh ...»، «Allow checking model router endpoints?» یا «Allow testing central model dispatch?» نمی‌پرسد. ایجنت موظف است خودش تصمیم بگیرد و فرآیند اعتبارسنجی را از طریق تست‌های لوکال، ماک‌ها، تست‌دابل‌ها و سرورهای محلی انجام دهد و نتیجه را در گزارش نهایی درج کند.
3. **بررسی سورس‌کد و روت‌ها به صورت کاملاً محلی:** تمام روت‌ها، دکوریتورها (`@router.get`, `@router.post`) و مدل‌ها مستقیماً از فایل‌های داخل مخزن لوکال خوانده می‌شوند، بدون هیچ اتصال SSH غیرضروری.
4. **بررسی استاتیک وابستگی‌ها و پکیج‌ها:** اطلاعات مربوط به نسخه‌ها و پکیج‌ها (`edge-tts`, `httpx`, ...) از روی فایل‌های مانیفست (`requirements.txt`, `pyproject.toml`, `package.json`, `Dockerfile`) بدون اجرای `pip show` روی سرور خوانده می‌شود.
5. **ارتقا و مدیریت پکیج‌ها در مانیفست‌های لوکال مخزن:** در صورت نیاز به ارتقای نسخه‌ها یا رفع باگ پکیج‌ها، ایجنت نسخه‌ها را مستقیماً در فایل‌های مانیفست پروژه تغییر داده و با تست‌های لوکال اعتبارسنجی می‌کند، نه با اجرای دستورات `pip install -U` روی سرورهای ریموت.
6. **بررسی وضعیت کانتینرها، شاخه‌ها و لاگ‌های گیت به صورت محلی:** اطلاعات سرویس‌ها، کانتینرها و پورت‌ها از روی مانیفست‌های لوکال (`docker-compose.yml`, `Dockerfile`) و وضعیت گیت (شاخه جاری با `git branch --show-current`, لاگ‌ها با `git log -n 5` و وضعیت تغییرات با `git status -s`) مستقیماً از روی مخزن محلی خوانده می‌شود، نه با اجرای SSH روی سرور ریموت.
7. **ماک کردن روترهای مدل و دیسپچ مرکزی:** اعتبارسنجی روترهای استدلال هوش مصنوعی و دیسپچر مدل‌ها در محیط لوکال با ترنسپورت‌های ماک‌شده انجام می‌شود تا نیازی به تست روی سرورهای ریموت نباشد.
8. **ماک کردن سرویس‌های صوت و سنتز گفتار (TTS):** اعتبارسنجی سرویس‌های صوت (`TTSService`)، چانک‌های صوتی و تاخیر سنتز در محیط لوکال با داده‌های ساختگی صوتی و توابع ماک ناهمگام انجام می‌شود تا نیازی به اجرای اسکریپت‌های بنچمارک روی سرورهای ریموت نباشد.
9. **ممنوعیت آزمون‌های زنده اینترنتی و ریموت**: ایجنت ملزم است کدهایش را با تست‌های لوکال، بیلد داخلی و سرور لوپ‌بک (`127.0.0.1`) راستی‌آزمایی کند نه با ارسال رکوئست به دامنه‌های عمومی یا اجرای دستورات ریموت روی سرور.
10. **اتوماسیون مرورگر و OS با متد «رانر تکی» (Single-Runner Batching)**: اگر کاربر از ایجنت بخواهد تب‌های فعال مرورگر (مثل cPanel، کنسول‌های کلود یا فیگما) را بررسی کند، ایجنت **نباید** ده‌ها خط دستور شل تکه‌تکه اجرا کند؛ بلکه یک اسکریپت تمیز پایتون یا اپل‌اسکریپت در پوشه پروژه می‌نویسد و آن را یک‌بار به شکل تمیز اجرا و خروجی ساختاریافته (JSON) را دریافت می‌کند.
11. **بررسی استاتیک دپلوی**: اطلاعات پورت‌ها، سرویس‌ها و داکر را مستقیماً از روی `docker-compose.yml` و `Dockerfile` می‌خواند نه با شلیک دستورات مکرر SSH.
12. **حفظ استقلال پروژه**: هرگز فایل‌های کانفیگ سیستمی بیرون از پروژه را دستکاری نمی‌کند.

### 🛡️ راهنمای فعال‌سازی دسترسی کامل (Full Access Setup)

اگر مایلید به ابزار کدنویسی خود دسترسی کامل بدهید تا در هیچ شرایطی پاپ‌آپ باز نکند، طبق راهنمای زیر عمل کنید:

#### ۱. گوگل آنتی‌گرویتی (Google Antigravity)
در فایل تنظیمات کاربری `~/.gemini/config/config.json`، کلید `globalPermissionGrants.allow` را با پیشوندهای مجاز تکمیل کنید:
```json
{
  "globalPermissionGrants": {
    "allow": [
      "command(git)",
      "command(pnpm)",
      "command(npm)",
      "command(python3)",
      "command(node)",
      "command(ssh)",
      "command(docker)",
      "command(curl)",
      "command(osascript)",
      "unsandboxed(python3)",
      "unsandboxed(bash)",
      "unsandboxed(osascript)",
      "unsandboxed(ssh)",
      "unsandboxed(docker)",
      "unsandboxed(curl)"
    ]
  }
}
```

#### ۲. کلود کد (Claude Code)
دستورات مجاز پروژه یا محیط را در کانفیگ مشخص کنید:
```json
{
  "allowedCommands": [
    "git *",
    "pnpm *",
    "npm *",
    "python3 *",
    "pytest *",
    "node *"
  ]
}
```

#### ۳. کرسر (Cursor)
با افزودن فایل `templates/AGENTS.md` به ریشه پروژه یا کانفیگ `.cursorrules`، ایجنت را موظف کنید که همواره درون سندباکس و با متد رانر تکی عمل کند.

## 🛡️ ۷ قانون طلایی این مهارت

1. **کشف و شناخت پروژه قبل از هر اقدامی (Discovery):** بررسی ساختار دایرکتوری‌ها، فایل‌های راهنما (`README`)، معماری (`docs/`)، نیازمندی‌ها (`package.json`, `go.mod`, `Cargo.lock`, `pyproject.toml`)، متغیرهای محیطی و فایل‌های داکر و استقرار.
2. **بررسی استاتیک به جای اتصالات ریموت بیهوده:** خواندن پورت‌ها و کانتینرها از روی `docker-compose.yml` و `Dockerfile`، بدون اجرای دستورات شبکه یا درخواست‌های دسترسی غیرضروری.
3. **درک وضعیت گیت (Git Understanding):** بررسی شاخه فعلی (`branch`)، وضعیت درخت کاری (`git status`) و حفظ تمام کدهای کامیت‌نشده‌ی کاربر.
4. **ساخت مدل ذهنی (Mental Model):** درک هدف بیزینس، معماری لایه‌ها، جریان داده‌ها و استراتژی تست قبل از تغییر حتی یک فایل.
5. **سیاست ممنوعیت سوالات ناتوان‌کننده و تاییدیه‌های تست (خودش تصمیم بگیره):** ایجنت نباید برای تست کردن، اجرای ماک، یا اعتبارسنجی اندپوینت‌ها اجازه بخواهد؛ باید خودش شجاعانه و مستقل تصمیم بگیرد، با ابزارهای لوکال اعتبارسنجی کند و گزارش را در پایان کار ارائه دهد. سوال فقط زمانی پرسیده می‌شود که اطلاعات اصلاً وجود نداشته باشد یا تغییر تخریبی باشد.
6. **پروتکل پاسخگویی استاندارد مهندسی:** ارائه تحلیل در قالب ۴ بخش در اولین پاسخ:
   - `## Understanding` (درک پروژه)
   - `## Current State` (وضعیت فعلی کد و گیت)
   - `## Plan` (برنامه اجرایی مرحله‌به‌مرحله)
   - `## Blocking Questions` (فقط موانع واقعی، در غیر این صورت هیچ)
7. **گزارش شفاف پایان کار (Completion Report):** ارائه گزارش نهایی شامل وضعیت موفقیت (`STATUS`)، فایل‌های تغییریافته (`CHANGES`)، اعتبارسنجی و تست‌ها (`VALIDATION`)، وضعیت استقرار (`DEPLOYMENT`) و موارد باقی‌مانده (`REMAINING`).

## 🚀 نحوه نصب و استفاده در ایجنت‌های مختلف

### ۱. گوگل آنتی‌گرویتی (Google Antigravity)
فایل `SKILL.md` را در مسیر اسکیل‌های محلی خود قرار دهید:
```bash
mkdir -p ~/.gemini/config/skills/agent-project-discovery-skill
cp SKILL.md ~/.gemini/config/skills/agent-project-discovery-skill/SKILL.md
```

### ۲. کلود کد (Claude Code)
```bash
mkdir -p .claude/skills
cp SKILL.md .claude/skills/project-discovery.md
```
یا محتوای `templates/AGENTS.md` را در فایل `CLAUDE.md` پروژه خود اضافه کنید.

### ۳. کرسر (Cursor)
فایل `.cursor/rules/discovery.mdc` را بسازید یا دستورالعمل زیر را در `.cursorrules` قرار دهید:
```markdown
Before making any code edits or asking questions, read and execute the discovery steps in SKILL.md.
Always begin your first response with the 4-part protocol (Understanding, Current State, Plan, Blocking Questions).
```

### ۴. گیت‌هاب کوپایلوت (GitHub Copilot Workspace)
متن فایل `templates/AGENTS.md` را در مسیر `.github/copilot-instructions.md` قرار دهید.

### ۵. راه‌اندازی سریع در هر پروژه دلخواه (۳۰ ثانیه)
کافی است تمپلیت آماده را دانلود و در ریشه پروژه‌تان بگذارید:
```bash
curl -sSL https://raw.githubusercontent.com/tmolavi/agent-project-discovery-skill/main/templates/AGENTS.md -o AGENTS.md
```
